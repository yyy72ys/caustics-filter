## §2 項目別統合裁定

### K1 — 輸送契約・交点選択・回折・受入テスト：不成立（GPT・Gemini を採用。Grok の条件付きを覆す）

Grok の条件付き成立は、その脚自身が挙げた残件と両立しない。Grok は Fresnel 捨て枝の扱い・ABSORBED 時の像寄与・デフォーカス込み PSF 全体の判定量・独立参照 B の非一意性を「設計判断を要する」と書きながら条件付き成立としている。これらは「書けば直る」の範囲を超えるため、不成立とする。親原文で裏取った。

(1) 空気側水面反射 L_glit の分岐欠落。親 §1 v4-4.3 ※R4 (2)（386–388行目）は「空気側から水面へ入る交点では Snell 屈折で水中へ進む（空気側に全反射はない）」とだけ書く。1 回の TR 呼び出しで表面反射 R_F・L_sky/sun → L_glit と水中屈折 (1 − R_F)・L_bed → L_bed の両方を返すなら単一 status（SURFACE 対 BED）と衝突し、屈折しか追わなければ表面グリッターがゼロになる。Gemini の指摘どおり。(1) の終端規則（366–370行目）も、MISS を「全成分を 0 とし、L_env にその方向の環境放射輝度を入れる」と書いており、L_env 自体が成分である以上「全成分 0」との語義が衝突する。

(2) 下面 Fresnel の片枝切捨て。親 (2)（390–394行目）は「反射と屈折のうち Fresnel 重みの大きい方へ進み、選んだ方の重みを放射輝度へ乗せる」とする。臨界角 48.61° 近傍で R_F ≈ T_F ≈ 0.5 のとき、捨てた枝のエネルギーは最大 50% に達する。捨てた重みの上限・テスト (6) の 5% との接続は固定されていない。決定性とエネルギー保存は別問題であり、両立には重み付き分岐または不偏選択の設計が要る。

(3) 4回打ち切りと物理吸収の混同。親 (2)（395–397行目）は上限 4 回で status = ABSORBED とし「打ち切った重みは記録する」とだけ書く。打ち切り残余エネルギーが像へどう寄与し、合否にどう接続するかの規則が無い。L_vol の積算も「輸送側の定義に従い、第4段は関与しない」（371–373行目）と輸送任せのまま、テスト (6) で総光量 5% を課すため、輸送段の吸収・散乱不保存と切り分けられない。

(4) 回折機構の実行規則と合否量の欠落。親 (3)（399–413行目）は幾何像への Airy 核畳み込みと N_w(x, y) = N・s_f/(s_f − f) を置くが、s_f は露光中に s_f(t) で動き、N・f は画素に依存しないため、積算後の単一 N_w 畳み込みの定義が閉じない。テスト (5)（468–475行目）は「波動光学の独立参照（瞳関数の FFT 伝播）で回折込み PSF を照合すること」と書くが、比較指標（中心強度・MTF・L2 差等）も合否閾値も無い。Grok の指摘どおり、ぼけ径・Airy 径の許容差だけではデフォーカス込み PSF 全体の誤差を測れない。

(5) 独立参照 B の割当てが一意でない。親（478–482行目）は参照 B を「(a)(b)(c) の少なくとも1つ」とする。テスト (1)(2) に (b) を充てる規定が無く、系統誤り検出の担保が弱い。Grok も同じ点を挙げている。

以上は文言の追加では閉じない。Fresnel のエネルギー扱い・L_glit 分岐・打ち切り規則・テスト (5) の合否量は設計の再考を要する。

### K2 — 50 mm補助分枝と窓幾何：成立（Gemini・Grok を採用。GPT の条件付きを、残件を記録した上で覆す）

3席とも分枝選択と数値の一致を確認した。補助分枝 f = 50.000 mm の正式採用・主分枝の現行無効化（親 §1 v4-4.1 ※R4 122–151行目、§9 #4）、同窓 h_a = 1.61144／3.74748／2.89546 m（最小 b_eff = 1.770／1.627／1.022 px）、同高 h_a = 1.11212／1.11212／2.03082 m（同 2.484／2.484／2.589 px）は再計算 §3.5 の確定値と一致する。Gemini は半画角（19.799°／14.799°／24.063°）も 50.000 mm から検算一致と確認した。Grok は同高版でメイン・対比の h_a・窓・b_eff が同一値になる点を「与件の対称性から算術的に妥当」と確認した。

GPT の条件付きの根拠は「同高版の窓と Snell 窓定義との対応を検算可能にすること」と「Snell 窓の再現をテストとして閉じること」である。しかし GPT 自身、最低条件 2 の閉鎖判定では「閉鎖」としている。分枝の選択と両版の数値併記という K2 の主張そのものは 3 席一致で検証済みであり、GPT の残件はテストの閉じ方の注記であって K2 の不成立事由ではない。残件として記録する：同高版の窓条件の対応を、実装者が再計算可能な形でテストとして閉じること（§5 R5 最低条件 3 へ繰り越し）。

### K3 — 旧契約の失効・Snell窓・PRESETS再現：条件付き成立（3席一致）

閉じた点：窓定義が Snell 主光線の厳密追跡へ置き換わり（親 §1 v4-4.1 物理的根拠 35–51行目）、旧式 W = W_s・(s/f − 1)・W_bed(s_f)・s_app 代入が現行無効化された（§9 #1・#2・#10）。§9 の無効リスト 10 件は、GPT・Gemini・Grok がいずれも網羅を確認した。PRESETS 再現誤差表（親 §1 v4-4.1 ※R4 92–108行目）の 3 枠の数値・丸め差（−0.00094／−0.00118／+0.00460 mm）・旧 f 誤差（−8.47%／−22.26%／−11.06%）は確定値と一致する。

残件：(1) 再現誤差 0 の検証力。親の表は f を W(f) = W_spec の解として二分法で求めた値で窓を再構成しており、誤差 0 は構成上ほぼ自明である。Gemini も「逆解なので誤差 0 自体は二分法の整合確認」と認めている。固定された Snell 精確焦点距離から順方向に窓を計算し、指定窓との差を評価する独立検証にはなっていない。(2) 旧評価順序の残存。親 §1 v4-4.4 ※R2（505–506行目）に「各時刻の評価順序は（水面状態→光輸送→焦点位置 s_f→PSF→センサー光量の蓄積）で固定する」が無傷で残り、§9 無効リストにも入っていない。案1 では s_f(t) で決まる合焦面上の点へ瞳サブレイを向けて初めて TR が呼べるため、光輸送 → s_f の順序は実行時に破綻する（Gemini の指摘を採用）。(3) §5 の進捗（R3）ブロックや v4-4.4 の ※R3 体制地図ブロックが「現行無効」と明示されているかは、短縮版では Grok が引用未確認としており、全文照合が要る。

### K4 — 3次元結合サンプリングと収束規則：条件付き成立（3席一致。ただし Gemini の開始インデックス指摘は設計の再考要素として記録する）

閉じた点：(u_pupil, v_pupil, t) の 3 次元結合列、Sobol 列（Joe–Kuo new-joe-kuo.6.21201）、Owen スクランブル、画素シード splitmix64(x + 2048y + 2^22・frame)、開始インデックス 1、N_total = 64 から 2^20 までの 2 の累乗倍増、Shirley–Chiu 写像へ一本化され、R3 の S／M 矛盾は解消した。シードに N_total が入らず n → 2n が同一列の延長比較になる点と、2^22・frame のビット非衝突（2048×2048 = 2^22）も Gemini が正しいと確認した。

残件：(1) 開始インデックス 1 は設計の再考を要する。親 §1 v4-4.4 ※R4（522–524行目）は「開始インデックス：1（原点の角点を避ける）」とする。Owen スクランブルはインデックス 0 自体を [0, 1)^3 へ一様ランダム化するため原点に留まらない。にもかかわらず [1, 2^k] を採ると、0 を欠き次の 2 進ブロックの先頭 2^k を混入させるため、すべての 2 の冪 N_total = 2^k で低差異ネットの層化性が崩れる（Gemini の指摘を採用。開始は 0 とすべき）。(2) Owen スクランブルの実装詳細（スクランブルの深さ・ハッシュ、splitmix64 の単一 64 bit 出力から 3 次元各軸の鍵をどう導くか、整数幅・オーバーフロー）が未固定で、異なる実装者が同じ列を得る保証が無い（GPT・Grok とも指摘）。(3) 倍増列の入れ子性。画素ごとに異なるスクランブルを掛けた列で n と 2n を比較する意味（同じスクランブル系列の prefix 比較か）が読み取りにくい（Grok）。(4) 収束判定の 1% ブロック除外。親 (6)（439–451行目）は 32×32 px ブロックを「全体平均の 1% 以上」で絞る。太陽グリッターが全体平均を押し上げた場合、肝心の床コースティクスブロックの大半が検査から脱落する（Gemini）。端数ブロック（1503 mod 32 = 31 の下端 31 px 帯）の処理、I_n が輝度か RGB 各成分か、「露光内グリッター像の時間積分重心」の算出対象も未定義である。(5) 上限 2^20 到達時の壁時間扱いは「記録する」だけで、適用外時の納品除外と設計差し戻しの接続は書かれているが運用上の閉じ方が弱い（Grok）。新規設計値 3e-3 と床 1e-3 の根拠・感度も示されていない。

### K5 — D_app適用マスクと範囲外画素：条件付き成立（3席一致）

閉じた点：θ ≤ 26.75° かつ κ < κ_crit を D_app の適用マスクとし、マスク外では D_app を未定義・外挿しない、役割を 3 用途に限定する、マスク外の結像は案1の再トレースへ送る、テスト (4) の評価点をマスク内かつ境界から 1 px 以上離れた位置に限定する、という整理がなされた（親 §1 v4-4.2 ※R4 223–299行目）。Δs 閉形式と検算例（N = 2.8 で 0.336 m、N = 16 で 2.020 m）は Gemini・Grok が完全一致と確認し、b_lim = sqrt((2 px)^2 − d_A^2) が体制地図の b_eff ≤ 2 px と同値であることも確認された。100 m 感度（0.51／0.25 px）も、許容差 max(0.5 px, 5%) の 5% = 1.74 px が効くため内側という Gemini の主張が成り立つ。

残件：(1) サブ条件の曲率統計が未測定。κ_crit = 1.0008/m に対してどの画素がマスク内に残るのか、テスト (4) を実行できるだけの評価点が存在するのかは確定していない。3席一致で「サブ曲率の測定なしにテスト (4) を合格扱いしてはならない」。(2) κ1・κ2 の算出方法が未固定。波面高さ場のどの解像度・どの差分演算子で主曲率を取るかが書かれておらず、推定法次第で M_app の境界およびテスト (4) の「境界から 1 px 以上内側」が動く（Gemini・Grok とも指摘）。(3) 100 m 感度 0.51 px は許容差 max(0.5 px, 5%) の境界付近であり、「内側」と断言するには余裕が少ない（Grok）。(4) 10% ぼけ換算の分母微差。R4 の 1.06／0.53／0.63 px は分母に s_s(s_s − f) を使った近似値で、厳密な薄レンズ分母 s_t(s_s − f) では 1.09／0.55／0.68 px になる（Gemini の検算を採用）。

### K6 — 斜め入射Coddington補正と角度適用：成立（Gemini を採用。GPT・Grok の条件付きを、親原文で裏取って覆す）

親 §1 v4-4.2 ※R4（261–272行目）は、入射角 θ_i（入射光線とファセット法線のなす角）に対して接線側 (R/2)・cos θ_i、矢状側 R/(2 cos θ_i) とし、D^(t) = h_a + cos θ_i/(2κ^(t))、D^(s) = h_a + 1/(2κ^(s)・cos θ_i) と置く。ここで κ^(t) は入射面内の法曲率、κ^(s) は入射面に直交する面内の法曲率であり、θ_i は「輸送側がファセットごとに与える（太陽方向と法線から決まる幾何量）」と明記されている。GPT の条件付きの根拠は「Coddington 式をどの面の法線・入射角・主曲率に適用するか、κ_t, κ_s をどの座標系で評価するかを、輸送側の局所面定義と完全に結びつける必要」だが、親は入射面・ファセット法線・θ_i の与え方まで定義しており、この接続は既に書かれている。Gemini は式が斜入射球面鏡の Coddington 標準形であること、1 − cos θ_i が 30° で 13.4%、40° で 23.4% と一致すること、対角半画角（32.692°／38.332°／46.939°、50 mm 版 24.063°）がすべて正確であることを検算で確認した。Grok の残件は「誤差百分率の再計算確認」と「対角半画角が光線軸角規則と完全に一致することの明示不足」で、いずれも軽微であり、親の半画角一覧（109–120行目）には「対角隅も自動的に判定を受ける」と明記されている。

ただし、κ^(t)・κ^(s) を離散高さ場からどう計算するかは未固定であり、これは K5 の残件 (2) として引き継ぐ。K6 の旗そのもの（補正式と角度数値）は閉じたと判定する。

### K7 — センサー幾何・E/A分離・旧文書の整理：条件付き成立（3席一致）

閉じた点：センサー幾何は算術的に整合している。2048×2048 の 36×36 mm マスター、画素ピッチ 36/2048 = 17.578125 μm、2048×1503 中央クロップの高さ約 26.42 mm、2048:1503 = 1.36261（736:540 は相対差 0.026% の近似）、15:11 を現行比として扱わない。E = 2.2／A = 2.6 はカメラ外のレガシーグレードとして保持し、第4段の物理計算へ混入させないという本人決定と整合している。§9 の R4-1〜R4-17 対応表と提出条件差し替えも前進した。

残件：(1) 文書の現行・履歴の切り分け。§1 内の注記の積層、§6 の提出条件・§8 の過去の訂正記録が、現行仕様と履歴の境界を曖昧にし得る（GPT・Gemini・Grok の 3 席一致）。(2) K3 の残件 (2) と同じ v4-4.4 旧評価順序の残存と、※ラリー反映の未確定宣言文（「固定するなら『…ハイブリッドである』と宣言すること」、親 496行目）が未確定形のまま残っている（Gemini）。(3) v4-4.4 の 50 mm 差し替え箇所が依然 ※R3 で差し替え の見出しの下に書かれている（Gemini）。(4) §8 の R3 訂正リストに「R3 時点の履歴であり現行無効箇所は §9」とする注記が無い（Gemini）。置き場申告の全体一致は、短縮版では Grok が引用未確認としており、全文照合が要る。

### K8 — 最終主張：不成立（3席一致）

K1 が不成立であり、K4・K5 にも実装・検証上の未閉鎖が残る。K2・K6 の改善は明確だが、全体の採用可能性を覆すものではない。Gemini の指摘どおり、R4 をそのまま実装発注すると、TR の反射枝・FFT 閾値・Sobol 開始点・ブロック基準・評価順序の未定義により実装者ごとに異なる結果が出る。「本人が設計を採用するか判断する段階」と「設計が実装可能な仕様として閉じている段階」は異なる。R4 は前者へ進める状態ではない。
