## やること（範囲は (a)＋(b) のみ）
- **(a) MSD 散乱窓の縮小**：MSD 散乱（1.08 s）は 1 ブロック 16.8 MiB の並べ替え先へのランダム書き込みで L3（12 MB）を溢れる。ブロック長 256 行は固定なので、MSD のバケットを「行×列の上位ビット」に細分化して散乱窓を縮める。
- **(b) LSD 走査の削減**：LSD（1.23 s）の 3 走査（min/max・count・scatter）を 2 走査に削る。
- **(c) はやらない**：幾何カーネルに行き先バケットを直接書かせる案は、幾何の変更を要するため本ジョブの範囲外。設計レベルの検討としてレポートに記録だけする。

## 禁止事項（破ったら FAIL）
- 幾何を触らないこと。`det_fast._geom_all` は import して無変更で使う。`fmod` は残す（`P - floor(P/S)·S` への置換は 1 ulp ずれる可能性があり、ビット一致の保証が崩れる。cf-0062 §6.6）。
- `row_block = 256` は固定（加算グルーピングの定義そのもの）。
- `det_fast2.py` 自体は変更してよいが、変更する場合は新しい実装ファイル（例：`det_fast3.py`）として作り、`det_fast2.py` は無変更で残すこと。本番の既定は `det_fast2` のまま変えない（本番配線は本ジョブではしない）。
- 既存の `*.py`（`det_fast2.py` を除く新規ファイル以外）は変更禁止。変更前後で全 `*.py` の SHA256 を取り、変更 0 件を証明すること。
- `run_prod_v4.py` は変更禁止。本番入口の検証は `run_prod_v4.py` 経由で行うが、ファイル自体は触らない。

## 必須ゲート（1つでも落ちたら FAIL 報告。リバート対象は新規ファイルのみ）
1. **等価性**：本番入口（`run_prod_v4.py`、既定 impl＝det_fast2）で frame 0・24 の C・flow・PNG が現行本番 det_fast2 および `out/prod/` 成果物と **max abs diff = 0.0**（差要素 0/4,194,304）、最終 PNG 画素一致（差 0/1,188,495）。追加で frames 0–5 の C・PNG が SHA256 バイト一致。
2. **速度**：堆積ステージと det_frame 全体の before/after を同一セッション・同一構成で測定し、倍率を記録すること。絶対値はマシン負荷で動くため倍率を主結果とする。改善が無ければ NO-GAIN として正直に報告（FAIL ではないが、配線の対象にはしない）。
3. **範囲**：既存 `*.py` の変更 0 件を前後ハッシュで証明。`out/prod/` への書き込み 0 件。
