# FIX-16: FPS計測を実フレーム数ベースに修正（適応制御の応答性）

## 問題（メイン側の実測で判明）
- FIX-15 の FPS（フレーム間隔EMA, α=0.05）は、低フレームレート時に実態と大きく乖離する。実測: 実描画が約1fpsの環境で表示FPSは 153→70 と緩慢に減衰するだけ（初期の軽い画面で種が入る＋サンプル到着が遅いため収束しない）。結果、自動制御（45未満で段下げ）が現実的な時間内に発動しない。表示値としても虚偽（1秒に1回しか更新されない画面で「60.5 fps」と出る）。

## 変更要件（app.js の計測方法のみ）
1. FPS を「直近の時間窓に実際に描画されたフレーム数」から算出する: 例として、フレーム描画時刻の履歴（直近2秒分）を保持し、`fps = 窓内フレーム数 / 窓の実効秒数` とする。評価・表示は 0.5 秒ごとに更新。
2. `window.__caustics.fps` と画面右下オーバーレイ表示、自動制御（FIX-15 の閾値 45/57・1秒評価・最短2秒間隔・3回継続で上げ）は、この新しい fps を使う。制御ロジックの閾値やラダー自体は FIX-15 のまま不変。
3. メディア読込や品質切替の直後に古い計測が残らないよう、窓履歴は直近2秒のみを保持する（自然に押し出される実装でよい）。

- 品質ラダー（倍率・グリッド）、自動制御の閾値・間隔、手動セレクト、シェーダー数式・較正値、env.js、その他すべて FIX-15 のまま不変。
