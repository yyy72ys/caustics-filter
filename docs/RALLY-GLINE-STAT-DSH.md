# G-LINE 統計化設計への攻撃レビュー（RALLY-GLINE-STAT-PROMPT 回答）

対象：単発 G-LINE → 窓ごと比の分布判定（R=5 × F=3, n=15、窓合格「平均 ≤1.05 かつ q90 ≤1.25」×4窓、写真ジッター床、G-LINE2 併用）への移行提案。
立場：攻撃的レビュアー。守らない。数値で殴る。

## D1：単発合否はモデルの性質ではない — STANDS（ただし証拠の言い方が盛っている）

根拠：3窓で比の範囲が 1.0 を跨ぐ（smooth x 0.91–1.07、smooth y 0.93–1.02、bark x 0.78–1.07）。単一 draw が閾値の上下どちらに落ちるかは引き次第。本番 seed が smooth y / bark x で FAIL 側を引いたのは不運の実例であり、モデル固有の FAIL ではない。ここまでは立つ。

反論（崩れる条件）：
- 「5本中0本」は思ったより弱い証拠。真の全窓通過率を p とすると P(0/5) = (1−p)^5。p=0.2 でも 0/5 の確率は 0.33。Clopper–Pearson 95% CI は約 [0, 0.52]、rule-of-three でも上限 3/5=0.60。つまり「通過率 30–50%」を排除できない。0/5 は「単発が脆い」の証明にはなるが「モデルが系統的に落ちる」の証明にはならない。
- frame 24 固定の話しかしていない。seed 方向の散らばりと frame 方向の散らばりを分離していないので、「単一フレームが悪い」のか「単一 seed が悪い」のか切り分けられていない。frame 0/47 では 5/5 通過する可能性が残る。
- bark y だけ見れば min 0.97 で 1 本は通過している。窓別には単発通過は普通に起きる。D1 を「だから分布にしろ」に使うのは正しいが、「だから現モデルはダメ」に使うのは誤用。

## D2：分布判定にすれば合否はモデルの性質になる（n=15＋SE明記が条件） — WEAKENED

方向（平均＋散らばりを見る）は正しい。条件の数え方が間違っている。

反論：
- n=15 は水増しであり、D5 と直接矛盾する。同一 realization の 3 フレームは同一パターンの時間発展であり独立でない。平均の SE を sd/√15 で計算すれば、真の SE（sd/√5 前後）より約 √3≈1.7 倍小さい。信頼区間が偽に狭くなる。
- q90 を n=15 で推定するのは無謀。n=15 の 90 パーセンタイルは上から 2 番目前後の順序統計量で決まり、1 点の入れ替わりで ~0.05–0.10 跳ぶ。bark y の max 1.29 / smooth 系の max 1.02–1.07 という散らばり幅からして、q90 推定のノイズは合否マージン（1.25 との距離）と同オーダー。ゲートがサイコロになる。
- 通常のブートストラップ（15 点から単純リサンプル）はクラスタ構造を無視するので q90 の CI をさらに甘く見積もる。クラスタ・ブートストラップ（realization 単位で resample）の指定がなければ「CI が境界をまたげば未解決」の運用は飾り。
- R=5 は分布の推定には薄い。平均の推定（n_eff=5、SE≈0.03–0.05 と見込まれる）にはギリギリ使えるが、q90 や裾の主張には足りない。「平均の SE を明記」が条件というなら、q90 側の条件は現 n では満たせないことを自白すべき。

失敗条件：フレーム間相関が高い（静止に近いループ）と n=15 の SE はほぼ sd/√5 の 1/√3 誤表示になり、平均≤1.05 の判定が偽の確信に変わる。逆にフレーム間でパターンが大きく変わるなら F=3 の取り方（0/24/47という位相の選び方）で平均が動く。どちらに転んでも n=15 は正当化されない。

## D3：写真側も分布、ジッター床が最小限の是正 — WEAKENED

「1 枚の写真の 4 窓を点としてモデル分布と比べるのは同じ誤りの裏返し」は正しい指摘で、ここは STANDS 級。問題は処方箋。

反論：
- 窓原点 ±24px シフトの sd（2.2/2.4/4.7/2.4‰、比換算 3.5/3.9/9.9/6.1%）は「写真の分布」ではない。窓配置感度の測定であり、水面・光・露出・別シーンという写真母集団のばらつきを含まない。これを σ 単位の分母にして「bark y +2.0σ、他 −1.3σ〜−0.4σ」と書くと、1 枚写真の薄さが統計的厳密さに化粧される。
  - 検算：bark y 超過 (1.120−1)×39.3=4.7‰ /2.4=1.96σ、smooth x (0.954−1)×63.7=−2.9/2.2=−1.33σ、smooth y −0.99/2.4=−0.41σ、bark x −2.56/4.7=−0.54σ。数値は合っている。だからこそ危険で、読者は「2σ の有意差」と誤読する。
- ジッターはどちらの画像のものか、提案文から特定できない。写真側の配置感度でモデル平均の超過を割るのは転移可能性の仮定（両画像で配置感度が同じ）が必要で、無証明。bark x のジッター 9.9% が大きいのは写真側の構造由来か窓定義由来か不明なまま、モデル側のばらつきの言い訳に使える。
- 「bark y の base 45.9 がシフト掃引最大 41.7 を上回る」は強い事実だが、これも単一配置 vs 掃引の比較で、写真母集団の上限ではない。1 枚写真の別配置・別撮影なら 45.9 を超える可能性を排除できない。

失敗条件：写真を 1 枚のままジッター σ を併記すると、レビュアーは「分布を考慮した」に満足して参照の薄さを追及しなくなる。最小限の是正が上限の是正として運用される。

## D4：「平均≤1.05 かつ q90≤1.25 ×4窓」は散らばりに較正されている — WEAKENED（較正という言葉が誤り）

現データとの整合性はある：窓平均 0.954/0.984/0.946/1.120 に対し 1.05 は bark y だけを落とす。q90≤1.25 は max 1.02–1.29 に対し bark y の裾だけを問題化する。本番 FAIL（smooth y 1.016、bark x 1.07）を平均では救い、bark y +12% を落とす。記述の通りに動く。

反論（だから較正ではない）：
- 提案文自身が「閾値 1.05/1.25 は観測ギャップへの配置値であって統計的導出ではない」と自白している。「較正されており」と「配置値」は両立しない。同じ 5 seed（×1 frame）のデータで閾値を置いて「分ける」と言うのは事後フィット（double dipping）。F=3 のフレーム分布はまだ見ていないのに、その分布に対する分離性能を主張している。
- マージンが薄い。bark y 平均 1.12 と閾値 1.05 の差 0.07 は、平均の SE（n_eff=5 で ~0.03–0.05 と見込まれる）の 1.5–2 倍程度。あと数本 seed を足せば平均が 1.05 を跨ぐ可能性は普通にある。smooth y 平均 0.984 も同様に上振れで 1.05 に触れる。q90 側は前述の通りノイズがマージンを食う。
- 多重比較の無視。4 窓×2 条件=8 判定の AND で「全窓合格」を取るなら、窓を増やすほど・条件を足すほど合格率は下がる。窓数を 4 に選んだこと自体が閾値の一部になっている。窓の定義（位置・サイズ・5–15px 帯）を変えれば 1.05/1.25 の意味が変わるのに、窓定義の固定手順がない。

失敗条件：誤った不合格＝将来 seed 追加で smooth 系の平均が 1.05 を上回る／q90 ノイズで 1.25 を跨ぐ。誤った合格＝bark y の裾がたまたま 1.25 を下回る 15 点を引く（q90 が上から 2 番目決めなので 1 本の幸運で通る）。どちらも n の薄さと事後閾値の合わせ技で起きる。

## D5：フレームは独立でない、実効 n は realization 数 — STANDS

正しい。唯一の無傷の主張。同一ループの frame 0/24/47 は同一 realization の時間断面であり、パターン realization 由来の散らばり（提案が正しくも振幅でなくパターン由来としている）からすれば自由度は増やさない。フレーム数を n に足すのは水増し。

ただし攻撃として：
- realization 間も完全独立ではない。同じモデル・同じ合成器・seed 連番（+1/+2/+3/+7）なら RNG ストリームの相関・共通の系統バイアスを共有する。モデル族の性質を語るなら実効 n は 5 未満の可能性もある。
- 「水増しするな」は正しいが「捨てろ」は間違い。フレームは時間的安定性（ちらつき・位相依存）の情報を含む。捨てるのではなく階層的に扱う（realization 平均を第一単位、フレームは within 分散として報告）が正解。D5 を棒にして F を無駄にする運用は攻撃される。
- なお D5 が正しいことは D2 の n=15 を直接殺す。両主張を同時に抱える設計は自己矛盾。どちらかを直せ。

## D6：stat と G-LINE2 は独立 2 軸、4 組合せ有意味、目を上書きしない — WEAKENED

決定軸の分離（量の分布 × 固定周期の有無）という整理は有用。G-LINE2 の数値（写真 21.1 / 問題作 25.4 =1.21× vs 格子 105.6/116.2 =5.0–5.5×、中央値必須、modal_frac≤0.20）は、単一窓 max=104（格子並み）が混ざる現実に対する誠実な処方で評価できる。

反論：
- 「独立」は無証明。depth（軸平行 5–15px 帯の変調深さ）と prom2d（2D FFT の固定周期ピーク突出度）は同じ帯域・同じ配向エネルギーを食っている可能性が高い。強い固定周期は depth も押し上げるはずで、2 軸は相関する。相関があるなら 4 象限の「すべて意味を持つ」は崩れ、(stat PASS × G2 FAIL：振幅の小さい綺麗な格子？) などのセルが空か、逆に (stat FAIL × G2 PASS：現在の bark y) ばかりになる。相関行列なしに独立を名乗るな。
- 「どちらも目の判定を上書きしない」は安全弁に見えて、ゲートの無力化条項だ。両ゲート PASS でも目が FAIL なら出荷停止、両 FAIL でも目が OK なら出荷？ その運用ならゲートは助言であってゲートでない。目の優先順位（拒否権か、タイ procedures か）を書かずに「上書きしない」と言うのは、失敗の責任を人間に押し付ける仕組み。
- 読み表の 4 組合せの解釈が未定義。「stat FAIL × G2 PASS = 量が多いが自然な揺らぎ」vs「stat PASS × G2 FAIL = 量は少ないが人工周期」の処置（直す／許す／再測定）がなければ、2 軸は飾り。

## 設計の失敗条件（誤合格／誤不合格が出る場合）

1. **q90 ノイズによる誤判定（両方向）**：n=15 の q90 は 1–2 点の入れ替わりで動く。bark y の裾がたまたま揃えば誤合格、smooth 系に外れ 1 点が混ざれば誤不合格。ブートストラップ CI（特に単純リサンプル）はこれを隠す。
2. **参照の薄さ**：写真 1 枚・4 窓・ジッターのみ。別撮影・別水面・別露出の写真母集団を持ち出されれば 1.05/1.25 は紙くず。bark y +2.0σ の「2σ」は配置感度単位であって母集団単位でない。
3. **フレーム相関の誤処理**：n=15 の SE で確信すれば誤合格方向、F を捨てて R=5 の平均だけ見れば時間的ちらつき（ループ位相で depth が跳ぶ作品）を見逃して誤合格。0/24/47 という位相選択自体が恣意的で、位相をずらせば平均が動く。
4. **閾値の配置値性**：1.05/1.25 に統計的根拠がないため、土台変更（stage 2 の本物 3D 床など）時の「測り直す」は無制限のゴール移動に使える。都合の悪い超過が出たら「土台が変わったので再較正」で閾値をずらせる運用は、ゲートではなく化粧。
5. **「未解決」の無定義**：q90 の CI が境界をまたげば「未解決」。で、どうする？ 出荷停止か、追加 seed か、目の判断か。処置がなければ「未解決」は先送りのラベルにしかならない。境界付近（今の bark y こそ境界付近）に案件が滞留する。
6. **窓定義の自由度**：窓位置・サイズ・5–15px 帯・depth 定義を固定せずに分布化しても、窓を動かせば平均も q90 も動く（sd 2.2–4.7‰ は depth 値の 4–10%）。作り手が窓を選び直せば通るゲートになる。

## 見落としている機構・論点

- **窓定義そのものの恣意性**：4 窓（smooth x/y、bark x/y）の選び方・原点・サイズが固定手順なし。±24px で sd 4–10% 動くことが分かっているのに、窓配置の事前固定（preregistration）がない。 pathological には窓をずらして通す最適化が可能。
- **depth 以外の統計量の方が向いている可能性**：変調深さ（‰）は外れ値・照明ムラに引っ張られる。バンドパワー積分・方向別 PSD・コントラスト分布の裾など、より安定で seed 平均の SE が小さい量があるはず。量の選択自体を分布安定性で選ぶ視点がない。
- **多重比較**：4 窓 AND × 各 2 条件。窓ごとの偽陽性を抑えずに AND を取ると、真の合格モデルでも窓数・条件数を増やすほど落ちる。per-window α の補正か、4 窓の要約統計（例：平均の最大・加重平均）への一本化が必要。
- **G-LINE2 との相関**：2 軸独立は仮定。同一データで depth と prom2d の realization 間相関を出せば一発で検証できるのにやっていない。相関が高ければ 2 軸でなく 1.5 軸。
- **seed プロトコル**：+1/+2/+3/+7 の 5 本はランダム標本ではない。連番 seed の RNG 相関、+7 だけ飛ばした理由、本番 seed の特別扱い。R の増やし方（独立ストリームの取り方）の規定がない。
- **正規化版と raw の二重運用**：振幅揃え正規化版でも範囲は同じ＝散らばりはパターン由来、という知見があるのに、ゲートが raw と正規化のどちらなのか不明。両方見て都合のいい方を通す余地がある。
- **時間構造の未モデル化**：2 秒ループの frame 0/24/47 がループの代表か不明。ループ位相依存・ちらつき周波数・時間相関長の測定なし。F=3 の根拠がない。
- **較正セットと検証セットの分離なし**：閾値を置いたデータと判定するデータが同じ。最低でも「置いた 5 本とは別の新規 seed で検証」の規定が要る。

## 採用するなら最低限直すべき点（優先順位つき）

1. **n の数え方と判定統計量を直せ（D2×D5 の自己矛盾の解消）**：n=15 を捨て、realization を第一単位にする。窓合格を「5 realization 平均 ≤1.05 かつ realization 平均の最大 ≤1.25（または全 realization 平均の上限）」に書き換える。SE・CI は n_eff=R=5 で計算し、フレームは within 分散として別報告。q90 を残すならクラスタ・ブートストラップ（realization 単位 resample、B と seed 固定）を明記し、R を最低 10（できれば 20）に増やすまで q90 は参考値扱いに格下げ。現 R=5 で q90 合否はサイコロ。
2. **閾値を仮置きに格下げし、検証分離と窓固定を先にやれ（D4 の事後フィットの封印）**：1.05/1.25 を「provisional、較正セット（現 5 seed×1 frame）で置いた仮値」と明記。新規の独立 seed（最低 5 本、別ストリーム）で検証してから本運用。窓定義（位置・サイズ・帯域・depth 算出・frame 位相・raw/正規化の別）を文書固定し、運用中の窓ずらしを禁止。多重比較の扱い（4 窓 AND のままか要約統計か）を決める。土台変更時の再較正 SOP（何を何本測って誰が承認するか）を事前に書く。
3. **写真参照の薄さを隠すな、「未解決」の処置と目の権限を書け（D3×D6 の逃げ道封じ）**：ジッター σ を「写真分布」と呼ばない。「単一写真＋配置感度」のゲートであることを明記し、σ 単位表示には「配置感度単位、母集団有意差ではない」の注記を必須化。q90 CI が境界をまたぐ／平均が閾値±1SE 以内に入る場合の処置（追加 seed 数、出荷可否、再測定条件）をフローチャート化。目の役割を「拒否権のみ」か「両方向の上書き権」か明示し、目がゲートを覆した事例の記録義務を付ける。G-LINE2 との相関（depth vs prom2d の realization 間相関）を 1 枚の散布図で確認するまで「独立 2 軸」を名乗らない。
