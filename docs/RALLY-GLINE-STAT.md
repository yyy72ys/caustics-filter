## 2. 収束した裁定（3脚以上が一致）

1. **n = 15 は独立標本数ではない。** 集計単位は realization で、実効 n は R = 5 に近い。n = 15 で SE を出せば最大で √3 ≈ 1.7 倍過小評価になる。D5 が正しいことが、そのまま D2 の n = 15 を殺す（設計の自己矛盾）。— 4脚一致。
2. **D2 の主張はこの形では立たない。** 分布を見る方向は正しいが、「分布化すれば合否はモデルの性質になる」は過主張。GPT・Gemini は WRONG、dsh・Grok は WEAKENED。正しい言い方は「指定した seed 生成条件・時間サンプリング条件下での生成分布の**推定**」（GPT）。
3. **q90 は現標本では判定量にならない。** 実効 n ≈ 5–15 での 90 パーセンタイルは実質、最大値か上から 2 番目で決まり、1 点の入れ替わりで合否マージンと同桁に跳ぶ。ブートストラップも元の極端値しか生まない。— 4脚一致。
4. **閾値 1.05 / 1.25 は較正ではなく配置値。** 観測ギャップに事後に線を引いたもので（double dipping / Texas Sharpshooter）、誤合格率・誤不合格率は未検証。「実測の散らばりに較正されている」という表現は使えない。— 4脚一致。
5. **写真ジッターは「配置感度」であって写真の分布ではない。** σ_placement ≠ σ_photo population。窓原点 ±24 px の感度は、撮影条件・水面状態・個体差のばらつきを含まない。「bark y +2.0σ」を統計的有意差と読んではならない（正しくは「配置感度の sd の約 2 倍に相当する超過」）。— 4脚一致（Grok は D3 を STANDS としたが同じ留保を付けている）。
6. **評価対象は「自然のコースティクス一般」ではなく「この参照写真への適合」。** 写真 1 枚とモデル分布の非対称性はジッターでは解消しない。— GPT・Gemini・dsh が明示、Grok も複数写真の必要性で一致。
7. **D6 の「独立」は未証明。** depth と prom2d は同じ 5–15 px 帯のエネルギーを食っており（パーセバル）、強い周期構造は両方を同時に押し上げる。実測の realization 間相関を取るまで「独立 2 軸」とは呼ばず、「補完的 2 軸」とする。— 4脚一致。
8. **多重比較の扱いが未定義。** 4 窓 × 2 条件 = 8 条件の AND は、窓別棄却率 10% でも全通過 ≈ 65.6%（Gemini の計算）まで落ちる。窓間相関を無視した単純 AND は厳しすぎるか緩すぎるかのどちらか。— 4脚一致。
9. **単発判定が運であること自体（D1 の方向）と、分布化への移行そのものは全脚が前進と認める。** 争点は「分布化した」という事実ではなく、その統計的な身分である。

## 3. 相違・単脚の捕捉（残す価値のあるもの）

- **D1 の証拠の読みの反転（Gemini）**： 「5 本中 0 本通過」は「単発が揺れる」証拠ではなく、むしろ「単発でも現行ゲートは 5/5 一貫して FAIL を返し、系統的超過を安定検出していた」証拠でもある。比較すべきは全窓合否ではなく**窓ごとの通過率のばらつき**。dsh も定量面から同方向： 0/5 の通過率の 95% CI 上限は ≈ 0.52 で、「通過率 30–50%」を排除できない。
- **フレーム選定のバグ（Gemini、単脚の具体的捕捉）**： frame 0 と 47 は 2 秒ループの境界を挟んで約 42 ms しか離れていない隣接フレーム。F = 3 は実質 2 位相しかない。採るなら等間隔 0 / 16 / 32。
- **単一 seed 判定は捨てるな（GPT）**： 出荷される作品は特定の 1 realization そのもの。その品質判定として単一 seed の測定は対象を限定して残すべき。分布診断と併存させる。
- **分母依存の非対称（Gemini）**： 同じ +4.5‰ の絶対過剰でも、比では smooth x +7.1% / bark y +11.5% と化ける。比の一律 1.05 に正当性はない。
- **seed プロトコルの未検証（dsh）**： seed+1/+2/+3/+7 はランダム標本ではなく、RNG ストリームの相関が未検証。realization 間の独立すら自明ではない。あわせて raw 比と振幅正規化版のどちらがゲートの対象か設計が曖昧（二重運用の余地）。
- **目の権限の温度差**： Gemini は「上書きしない」は抜け道であり、不合格時は原則ブロック（例外は理由の明文化必須）とすべきと主張。GPT は目の判定を残すことを支持。dsh は権限の種類（拒否権のみか両方向か）と、覆した事例の記録義務の明示を要求。運用の厳しさで割れている。
- **Grok の D3 = STANDS** は他 3 脚（WEAKENED）と温度が違うが、「ジッターだけでは足りず複数写真が要る」という実質では一致している。

## 4. 採用前に設計が直すべき点

1. **集計単位を realization に統一する。** n = 15 の表記を捨て、SE・CI は realization 平均（R = 5）から計算する。q90 は判定量から格下げして参考値とするか、R を最低 10–15 に増やす。ブートストラップを使うなら realization 単位のクラスタ・ブートストラップを必須とする。
2. **フレーム抽出を等間隔位相（0 / 16 / 32）に直し、フレーム間相関 ρ を実測する。** ρ が分からなければ F の設計根拠がない。フレームは捨てず、realization 内の時間変動として階層的に報告する。
3. **閾値 1.05 / 1.25 は「暫定配置値」と明記する。** 閾値を置いた 5 seed とは別の、新規の独立 seed 群で検証してから本運用に入る。窓定義（位置・サイズ・帯域・depth の定義）・frame 位相・raw/正規化の別を事前に固定（事前登録）し、運用中の窓ずらしを禁止する。
4. **ジッターの呼び方と表示を直す。** 「写真の分布」と呼ばない。「配置感度（測定床）」として併記し、σ 単位の表示には「母集団の有意差ではない」の注記を必須とする。可能なら複数枚の写真で参照分布を取る。評価対象は「この参照写真への適合」と明記する。
5. **多重比較の扱いを決める。** per-window の補正か、窓間の共分散を入れた同時判定か、要約統計への一本化か、いずれかを採用前に固定する。
6. **G-LINE2 との相関を実測する。** 同一バッチで depth と prom2d の realization 間相関を出し、それまでは「独立 2 軸」ではなく「補完的 2 軸」と呼ぶ。
7. **「未解決」の処置と目の権限を文書化する。** CI が境界をまたいだ場合の追加 seed 数・出荷可否・再測定条件の手順と、目がゲートを覆す権限の範囲（拒否権のみ／両方向）と記録義務を決める。
8. **設計の地位を改める。** 本設計は「統計的合否ゲート」ではなく「複数 realization による分布診断」として採用する。単一 seed の測定は、提出作品そのものの品質判定として対象限定で残す。

## 5. 統合では決着できない未決事項

- フレーム間相関 ρ の実測値がない（F と位相の最適設計が決められない）。
- 参照写真の母集団（複数枚・別条件）が未取得。写真側の真の分布は未知のまま。
- depth 以外の統計量（尖度・歪度、方向別 PSD、45° 方向を含む評価）が分布判定に向くかどうかは未検証。
- seed 列（+1/+2/+3/+7）の RNG 独立性は未検証。realization の増やし方の規定がない。
- 土台変更時（stage 2 の本物の 3D 床）の再較正の具体的手順（何を何本測り、誰が承認するか）が未定。「測り直す」がゴールポスト移動に使われる危険を四脚が指摘している。
