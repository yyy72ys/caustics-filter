- 本設計案は未実行の設計である。**未実行であること自体は不成立の理由にしない。** 問うのは、実行した場合に判定規則が閉じているか——つまり、測定結果が出たときに結末への変換が一意に定まるか、判定不能・未決・適用外といった例外状態の接続先がすべて事前に固定されているか——と、数値の主張が正確かである。

### 主張（設計案が立てる設計主張）

#### K1 — 変更点の同定は完全か（_realise 206–208行が唯一の量子化経路か）

争点:
(i) _realise の外の量子化経路: 一次資料 cf-0075 §2 は、量子化に触れるコードとして _realise の3行のほかに `run_v4_1_11.py:360`（保存された omega_q から n_idx を `rint(ω_q/Ω0)` で復元）と同 `:386`（`lut = np.exp(1j * OMEGA0 * float(t) ...)` という Ω0 を直接使う場の進行）を挙げ、同 §7 は「`WindProvider.fields` は各モードを `exp(i·n·Ω0·t)` で進める」と書く。プローブ場の生成がこれらの経路のどれかを通るなら、_realise の変更だけでは場は非量子化されない。設計案は「記録ビルダは使わない」とするが、実験専用スクリプトが場の進行に実際に呼ぶ関数（`_cascade_fields` なのか、別の経路なのか）は本文で特定されているか。変更点の完全性は、OMEGA0／omega_q の全参照箇所の棚卸し（grep 監査）なしに主張できるか。

(iii) 属性名の意味の反転の波及範囲: コピーでは `omega_q` に真の ω が入る（リスク R5、158 行目）。実験スクリプト以外の読み手——特に量子化を前提に `rint(ω/Ω0)` でインデックスを復元する類のコード——がコピーの状態に触れる経路は、本当に記録ビルダだけか。読み手の列挙は本文で閉じているか。

#### K2 — 判定基準は事前に閉じているか（R_field の閾値 0.80／0.50 と予測帯 [0.0423, 0.0705]）

設計案は次の通り主張する（§1.3、31–43 行目）: 主判定量は R_mode（モード集合の残存比、分母 0.0680）と R_field（プローブ ν の残存比、分母 0.0906）である。結末 A「紙の結論が場で確認される」は R_field ≥ 0.80 かつ gap_probe（非量子化場）が予測帯 [0.0423, 0.0705] の中にあること。予測帯は 0.0564 ± 25%（cf-0077 の前例）で作り、0.0505 を含む。結末 B「量子化が場では残りを説明する」は R_field ≤ 0.50（gap_probe で 0.0453 以下）。中間（0.50 < R_field < 0.80）または帯の外は決着をつけない。判定は5シード平均で行い、シード単独の判定は禁止する。

争点:
(i) **結末 A の同時成立可能性（プロンプト作成側の検算。必ず自ら検算すること）**: R_field ≥ 0.80 は、分母 0.0906 に対して gap_probe ≥ 0.0906 × 0.80 = 0.0725 を意味する。しかし予測帯の上限は 0.0705 であり、0.0725 > 0.0705 である。すなわち結末 A の2条件は同時に満たし得ず、A は空集合ではないか。さらに、場が紙の比率どおり（残存比 0.829）に振る舞った場合の gap_probe は 0.0906 × 0.829 = 0.0751 で、帯の外（上限超）になる。設計案が「紙の結論が場で確認される」場合に予測する値そのものが自らの A の帯に入らないとすれば、判定基準は測定前に閉じているどころか、最もありうる結果を「決着なし」へ倒す構造になっていないか。
(ii) 尺度の取り違え: 予測帯 [0.0423, 0.0705] はモード集合のギャップ（0.0564、量子化側 0.0680）から作られている。一方 gap_probe の量子化側の値は 0.0906 で、モードのギャップとは尺度が違う（プローブ ν はモード ν と系統的にずれる量であり、cf-0075 §7 の貼り替え参考値でもギャップは 0.0747 でモードの 0.0564 とは一致しない）。モード尺度の帯をプローブ量の判定にそのまま使うことは正当か。正当でないなら、帯はプローブ尺度で作り直すべきではないか（例: 貼り替え参考値 0.0747 を中心とする帯）。
(iii) 閾値 0.80／0.50 の出自と場への転用: この2値は cf-0075 §5 が紙の再計算に対して事前固定した分岐（|gap_true| ≤ 0.5·|gap_q| → 主因、≥ 0.8·|gap_q| → 主因でない）の流用である。場の測定には紙にない分散要因（有限窓の漏れ、折り返し、プローブ推定のばらつき）が加わる。同じ閾値を場の量へ無調整で転用する根拠は本文にあるか。25% という帯の幅も cf-0077 の前例の引用のみで、本実験のばらつきからの導出ではない。この2点は「事前に固定した」ことと「妥当な値である」ことは別である、という批判に耐えるか。
(iv) 0.0505 の二重の現れ: 本番シード単独の gap_true = 0.0505 と連続スペクトルの解析ギャップ 0.0505 が4桁一致している（§1.2、29 行目）。設計案は 0.0564 を主たる予測値、0.0505 を「下側の参照値」とし、帯の説明では「[0.0505, 0.0564] を中心とする許容帯」とも書く（40 行目）が、実際の帯は 0.0564 ± 25% で作られており、2つの作り方が同居している。0.0505 の一致は独立な裏付けか、偶然の一致か。本文はどちらとも判定していない。この未判定の上に帯の下側の意味を置いてよいか。
(v) R_mode の判定上の位置: §1.3 は R_mode を「主判定量」の1つに挙げるが、結末 A／B の条件には R_field しか現れない。R_mode は §4.2 の内部ゲート（期待値 0.829）であって判定量ではないのではないか。判定量とゲートの混同は、統合や報告の段階で「2つの主判定量が一致した／しない」という誤読を生まないか。

(iii) 同じ窓 ≠ 同じバイアス: 量子化場は T_obs = 32 s（= 8 s の4倍）の窓では厳密に周期的であり、矩形窓でも漏れは生じない。非量子化場は同じ窓・同じ窓関数でも漏れる。窓を同一にすることは「扱いを揃える」ことにはなっても、モーメント推定のバイアスを両腕で等しくすることにはならない。この非対称なバイアスが、測りたい効果（ギャップの 17% 級の変化）と同程度になり得ることは、設計の段階で見積もられているか。未決 R2（155 行目）が窓の選択を段2の前へ送っているのは妥当な先送りか、それとも判定基準の閉じ方として不十分か。
(iv) 折り返しの非対称性: §4.3（117 行目）は帯の外（75.4 rad/s 超、P5 で |H0|² の約0.1%）の折り返しを「両腕で共通の既知の限界」とする。しかし量子化 ω は Ω0 の整数倍に乗り、真の ω は乗らないため、折り返して帯内へ落ちる先は両腕で系統的に異なる。リスク R3（156 行目）自身が「ギャップへの影響が完全に対称とは限らない」と認めている。本文の「共通」という記述と R3 の認め方は矛盾しないか。SWELL 側の帯外シェア（P5 の 0.1% に相当する数値）は本文にあるか。
(v) 前提仕様の未検証: 実験の中心測定であるプローブ仕様（点・記録長・サンプリング・窓）は、cf-0067 の保存 npz を段2の前に実物確認することが前提であり、本設計の時点では未確認である（R1）。設計案の他の部分（判定帯・コスト）がこの未確認仕様に依存している範囲は正直に切り分けられているか。

#### K4 — 段ゲートは分離を保証するか（H0 ビット一致、ν_mode の一致、量子化誤差ノード）

設計案は次の通り主張する（§4.2、104–111 行目）: 段1で本番シードの2条件を先に確認する。コピーの H0 が量子化側とビット一致すること。コピーの ν_mode が cf-0075 の ν_true（seed 1 で P5 0.3309／SWELL 0.3814）と一致すること（「float32 保存の丸めを超える差が出たら止める」）。コピーの `_quantisation_node` の max 相対誤差が float32 水準（1e-6 未満）まで落ちること。この段が通れば5シード×2条件へ広げ R_mode を出し、期待値は 0.829 で、紙の再計算と同値になるはずである。

争点:
(i) ν_mode ゲートの許容差の欠落: 「float32 保存の丸めを超える差」は数値で固定されていない。コピーの ν_mode は float32 で保存された ω から計算され、cf-0075 の ν_true は（紙再計算として）float64 の ω_true から計算されたはずであり、両者の差の期待規模（相対 1e-7 級の ω の丸めが ν へどう伝わるか）は見積もれるはずである。許容差の数値がないゲートは、測定後に「超えた／超えていない」を一意に判定できるか。未決 R8（161 行目）がこの扱いを「仮置き」と認めていることと合わせて、ゲートとして閉じていると言えるか。
(ii) H0 ビット一致の保証範囲: ビット一致は乱数の発生順と |H0|² の同一性を示すが、モード集合の同一性には k の配列・cascade 分割・モードの対応付けの一致も要る。H0 の一致だけで「同じモード集合」と言えるか、それとも k と分割の照合もゲートに要るか。また照合相手は「cf-0075 が読んだ同一状態」であり、cf-0075 は状態を自前スクリプトで構築して読んだ。異なるスクリプト・異なる配置（コピーは本番 workdir の外）でのビット一致は、乱数発生器の実装詳細（シードの使い方、発生順）が両者で同一であることに依存する。その依存は本文で確認されているか。
(iii) 量子化誤差ノードの定義の未引用: ゲートは `_quantisation_node` の「max 相対誤差」が 1e-6 未満になることを要求するが、そのノードが何と何の相対誤差を測るかは本文に引用されていない。もし誤差の定義が「保存 ω と分散関係の真値との差」であればコピーで 1e-7 級に落ちるのは自明に近く、ゲートはコピーの正しさの確認として弱い。逆にもし「保存 ω が Ω0 の整数倍からのずれ」であれば、コピーは設計上必ず落ちる（ゲートが実験を止める）。どちらの定義でも結論が変わる以上、定義の引用なしにこのゲートは審査可能か。
(iv) R_mode の同値性の意味: 段1のゲートがすべて通れば、R_mode = 0.829 は構成上ほぼ自動的に出る（コピーの ν_mode は紙再計算と同じ計算だからである）。設計案 §4.2（111 行目）も「紙の再計算と同値になるはず」と書く。したがって R_mode は物理の証拠ではなくコピーの正しさの確認である。その格付けは本文で一貫しているか（K2 争点 (v) の「主判定量」の呼び方と整合するか）。

#### K5 — 隔離の証明は十分か（本番無変更の2段証明）

設計案は次の通り主張する: 本番生成器は一切変更しない。実験は本番 workdir の外の実験専用ディレクトリに置いたコピーに対してのみ行い、本番の import 経路に混ざらない配置にする（§5、125–131 行目）。証明は cf-0075 §9 と同じ2段証明——段0で本番 workdir 配下の全 `*.py` の SHA256 を取り、段3で再取得して変更 0 件を示す（§4.1、99–102 行目／§4.4、120–123 行目）。コピー側の差分は §2 の1箇所＋docstring のみであることを diff で証明する。成果物は専用ディレクトリ（VM 側 `delivery/omega-unquant/`、PC 側 `out/omega-unquant/`）に分け、非量子化場の出力には「8 s で閉じない・ループ不可」を明記する。

#### K6 — コスト見積もりと結末ごとの分岐は妥当か
