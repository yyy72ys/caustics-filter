## 3席の合意点（直しの核）

1. **D1 の有限性と格子安定性は別問題**（3席一致）。連続場の {C > T} の面積が有限なのは正しいが、736×540 画素の超過カウントが水面格子を変えても安定することはそこから導けない。境界画素の出入りが直接の反例になる。Gemini の実測指摘が最も鋭い：fold 発散の話なら細格子化で std は増えるはずだが、実測は 0.9361 → 0.6344 → 0.4333 → 0.3092 と単調減少し、p99 も 1024² の 2.2339 から 2048² の 1.8386 へ −17.68% 低下している。つまり観測されているのは特異性の発散ではなく粗格子の離散化ノイズの平均化であり、§1.3 の推論は実測の減少方向と整合しない。
2. **D2 の弱収束は有限の2格子間安定の根拠にならない**（3席一致）。弱収束は連続テスト関数に対する漸近的な存在定理であり、到達可能な 1024² と 2048² の間のビン移動数が 1%（3,974 画素）以下に収まることは別問題。p99 の −17.68% の動きは [2,4) ビンから [1,2) ビンへの大量流出を示唆する。
3. **D1(b) の「数値的に中立でもある」は分類誤り**（3席一致）。測る対象の変更は大原則の (b) 実在の物理への対応であり、(a) 数値的中立ではない。「中立」の語を削除する。
4. **許容幅が実測前に固定されていない**（3席一致）。D1 ±0.5%（397,440 × 0.005 = 1,987.2 → メモは 1,987）と D2 1%（3,974.4 → 3,974）はいずれも「案」で、切り捨て規則が本文に固定されていない。§7 は数表を見てから幅を決める手順になっており、§6 の「結果を見てから幅を決めると甘くする行為になる」という禁止と自己矛盾している（K5）。幅を超えた場合の扱い（FAIL か設計棄却か）と、対比枠の校正で FAIL した場合の扱いも未定義。D2 のビン境界感度確認も §7 に組み込まれていない。
5. **G-CONV の保証対象は std と p99 であり、分布全体ではない**（3席一致）。§5 理由1の「C の水準・分布が格子に依らないこと」という読みは定義を超えた再解釈。G-PEAK（std 比 1.436／p99 比 1.333）が同じ std・p99 に依存しているのに波及が切り落とされている。G-LINE、写真比較、ぼやけ判別の rms コントラストなど std・コントラスト水準に依存する用途の棚卸しもない。
6. **D3・D4 は候補の水増し**（3席一致）。D3 は対象のずれ「大」を自認しながら代替候補に並べ、連結成分数は (d) で完全一致を要求できるとしつつ (e) で合体・分離で跳ぶと認める自己矛盾がある。D4 は既存の G-ENERGY の再掲で、相対誤差 1e-9 は実数であり要件 (i)「判定量が整数」に適合しない。両方とも候補から外し、D3 は補助監査、D4 は既存の基礎監査へ格下げする。
7. **X2 の一括却下は誤り**（3席一致）。順位統計（中央値・分位点）はモーメントではなく、D1 の超過測度と数学的に双対な量（C > T の画素数が全体の 1% 以下 ⇔ p99 ≤ T）である。log-std の却下は正しいが、分位点まで「連続量のモーメント」として却下する論法は D2 自身の根拠を掘り崩す。
8. **X1 は実装回帰監査として必須化する方がよい**（GPT・Grok が強く主張、Gemini は格付けを妥当としつつ反対しない）。transport_mesh_fast のビット一致は自然の正しさを保証しないが、実装変更による結果変化の検出には必須である。
