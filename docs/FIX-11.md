# FIX-11: 前方パスの輝度を「頂点解析密度の補間」から「フラグメント微分による幾何面積比」へ

## 診断（メイン側が現行 shader.js を精読して特定）
- 現行 SPLAT_VERT は頂点ごとに有限差分ヤコビアン det を計算して vLight とし、SPLAT_FRAG はその補間値を加算出力するだけになっている。
- このため fold 線が三角形の内部を横切っても、頂点が det≈0 の近くに座らない限り明るくならない。明部が「頂点に座った点」としてしか現れない（FIX-7〜10 で不変だった点状欠陥の構造的原因）。
- 輝度が三角形の実際の着地フットプリントと結びついていないためエネルギー保存も保証されず、平均ドリフト（深海 0.76 等）の一因にもなっている。

## 原典（Evan Wallace「Rendering Realtime Caustics in WebGL」— 前方方式の原点）
- 頂点では oldPos（変位前の表面点）と newPos（屈折後の着地点）の両方を varying で渡し、フラグメントシェーダで画面空間微分から面積比を出す:
  - oldArea = |dFdx(oldPos)| × |dFdy(oldPos)|
  - newArea = |dFdx(newPos)| × |dFdy(newPos)|
  - 輝度 = oldArea / newArea
- 三角形が fold を跨ぐと着地フットプリント自体が縮むため、頂点位置に依らず線として明るくなる。重なった三角形は加算ブレンドで多分岐合算になる（現行どおり）。
- 微分はフラグメント側でのみ使う。WebGL1 の頂点シェーダでは微分は使えない（FIX-7 の fwidth コンパイル失敗は頂点側で使ったため）。合成パスの FRAG は既に fwidth を使用しており、OES_standard_derivatives の経路は本コード内に実績がある。

## 実装要件
1. **SPLAT_VERT**: vLight を廃止し、vOldPos（= p、P_SCALE 空間）と vNewPos（= q、同空間）を varying で出す。着地点 q の計算（waveStateDisp・帯域別ゲイン・H ジッタ・CHOPPY・太陽オフセット・DISP_K の効き方）は現行どおり一切変えない。環境→水の状態→着地点の経路は不変。
2. **SPLAT_FRAG**: `#extension GL_OES_standard_derivatives` を有効化し、det相当 = newArea / oldArea として、現行の軟正則化と同形で density = oldArea / sqrt(newArea² + δ² × oldArea²)（δ² = uDelta2Fwd、現行定数と整合させる）。加算ブレンド (ONE, ONE) は現行どおり。拡張が使えない環境では従来の後方分岐にフォールバックする（現行の fallback 構造を維持）。
3. **CPU ミラー（verify-node 用）も同仕様に合わせる**: 前方パス分については頂点解析 det のミラーを廃止し、三角形ごとの幾何面積比（3 頂点の old/new 位置から面積比を計算し軟正則化）で密度場を再構成する。
4. **DISP_K 再較正（単一較正のみ）**: 新評価の下で K=1.5〜5.0 を掃引し、下記の受け入れ指標を全プリセットで満たす K を選ぶ。掃引表と採用理由を RESULT.md に記録する。

## 指標の是正（理由つき）
- 変位 std 0.02〜0.15 のハードゲートは廃止し、報告値（診断情報）とする。理由: std は「折り畳みが起きるか」の代理指標だったが、fold の有無は変位の大きさではなく変位の勾配（曲率×水深）で決まる。FIX-10 の掃引で、直接指標（max・相関・平均・CV）が K≈2 で全て満たされる一方 std だけが未達となり、代理指標が直接指標と競合することが実証された。以後は直接指標で判定する。
- 受け入れ指標（全プリセット）: 平均 1±0.15 / 最小 ≤0.5 / 高解像 max 6〜12 / 隣接相関 ≥0.5 かつ FIX-5 水準以上 / 面の指標 CV ≥0.25 / 8 秒ループ一致 / 有限性。従来の回帰項目は全 PASS を維持。
