# G-LINE-stat 閾値検証 — 事前登録（PRE-REG-GLINE-STAT）

**登録日： 2026-11-14（測定前）。DESIGN-GLINE-STAT.md（ADOPTED 2026-11-13）§2 の本運用条件にもとづく。**
**地位： 本検証は閾値の検証であって、モデルの合否判定ではない。合否は出さない。**

検証する問い： 暫定配置値 1.05（平均）／1.25（q90）は、閾値を置いた 5 seed とは別の新規独立 seed 群でも、1.12 と同じ方向の読みを与えるか。すなわち (a) 4 窓の realization 平均の方向（1 を上回るか下回るか）が 1.12 と一致するか、(b) bark y の系統的超過が独立 seed でも残るか、(c) q90 が判定量として使えるだけ安定に推定できるか。

## 固定するもの（測定後に動かさない）

### 参照写真と窓（1.10 / 1.12 と同一、凍結）
- 写真の 4 窓 depth（‰）： smooth x 63.7 / smooth y 61.6 / bark x 47.4 / bark y 39.3。
- 窓の位置・サイズ・帯域（軸平行 5–15 px）・depth の定義は v4-1.10 のものと同一。測定中の窓ずらし・定義変更は禁止。
- 配置感度（1.10 §9.10 の窓原点シフト sd）： smooth x 2.2 / smooth y 2.4 / bark x 4.7 / bark y 2.4‰。比の単位では 3.5% / 3.9% / 9.9% / 6.1%。配置感度は写真の分布ではない（DESIGN §1）。

### 測定対象とフレーム
- 対象は 1.12 と同じ本番パイプライン（warp-only の 4 窓 depth）。主対象は **raw 比**（Sn は副表示のみ）。
- 検証フレームは **0 / 16 / 32**（等間隔位相、DESIGN §1）。frame 24 は 1.10/1.12 との連続性のため参考記録として測るが、検証の判定には使わない。
- G-LINE2 軸も同じバッチから出す： realization ごとの prom2d（24 窓中央値）と depth との realization 間相関を測る。独立性の判定はしない（DESIGN §3）。

### 集計（realization 単位）
- 窓ごとの主統計は realization ごとの代表値（その realization の 3 フレーム平均の比）の列。平均・SE・90% CI はすべてこの R 本から計算する。実効 n = R（= 10）。フレームをばらした n = R×F 表記は使わない。
- CI は realization 単位のクラスタ・ブートストラップ（5,000 回）。フレームをばらして並べ替える素朴なブートストラップは使わない。
- フレーム間相関 ρ は仮定せず実測する（窓内中心化プール 0–16 / 16–32 / 0–32、1.12 と同じ方法）。
- q90 は**参考統計**として記録する。判定量への復帰は下の判定規則 (iii) による。

### 閾値（暫定配置値のまま）
- 平均の参照線 **1.05**、q90 の参照線 **1.25**。この検証では閾値の数値を変えない。新しい閾値を提案しない。

## 判定規則（測定前に固定 — 結果を見てから変えない）

1.12 の realization 平均（4 フレーム平均の比、R = 5）： smooth x 0.953 / smooth y 0.999 / bark x 0.932 / bark y 1.056。

- **(i) 方向の再現**： 新規 10 本の realization 平均が、4 窓すべてで 1.12 と同じ方向（1 を上回るか下回るか）を示し、かつ 1.12 の平均が新規 10 本の 90% CI の中に入る（または CI が重なる）こと。1 窓でも方向が反転したら (i) は不成立。
- **(ii) bark y の系統性**： bark y の realization 平均の 90% CI が 1.0 を上側に外すこと（系統的超過が独立 seed でも残る）。
- **(iii) q90 の復帰条件**： q90 のクラスタ・ブートストラップ 90% CI の幅が 4 窓すべてで ≤ 0.10 の場合に限り、q90 を判定量への復帰候補として記録する（復帰の決定自体は別途、本人の判断）。1 窓でも幅が 0.10 を超えたら q90 は参考統計のまま。
- **未解決の処置（DESIGN §2）**： realization 平均の CI が 1.05 の参照線をまたぐ窓があれば「未解決」とし、realization を +3 ずつ追加して再測定する（上限 R = 15。追加 seed は同じ RNG の続き `integers(0, 2**63, size=3)` をこの順で使う）。上限でも解けなければその旨を明記して報告する。

## 検証の結論の出し方（ジョブのレポートが書くこと）

- 上の (i)(ii)(iii) それぞれについて「成立／不成立」を、数値表（窓ごとの realization 平均・SE・90% CI・q90 とその CI 幅・ρ）とともに書く。
- **閾値 1.05 / 1.25 が運用値になるのは (i) と (ii) が両方成立した場合のみ**。その場合も「運用値への格上げ」は本人の決定であり、ジョブは格上げを宣言しない（証拠を出すまで）。
- (i) が不成立の場合： 1.12 のパターンは seed 族の運だった可能性が高く、閾値は暫定配置値のままとする。設計の見直し（ラリーへ戻す）を提案の形で書く。
- (ii) が不成立の場合： bark y の系統的超過は確認できず、1.05 の参照線は bark y を分ける線として支持されない。閾値は暫定配置値のまま。
- 4 窓 AND の単一合否は出さない（DESIGN §2）。窓ごとの推定をそのまま報告する。
- 目の権限（DESIGN §6）は本検証では変わらない。

## 検証しないこと

- 新しい閾値の提案・窓の変更・写真の差し替え。
- C レーンへの分布化（DESIGN §8-8）。
