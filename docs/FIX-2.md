# 修正指示 FIX-2 (作り方の根本変更: 模様合成 → 水の状態シミュレーション)

## ユーザーの判定 (2026-11-09)
- 現行版は「ただ白い線がウネウネしてるだけ」。奥行き・リアルさ・複雑さがない。
- 求めているのは「層を重ねる」等の見た目の工夫ではない。
  **環境の影響を受けた水の"状態"そのものを作り、その水を通した結果として像が得られること。**
  つまり: 環境 → 水の状態(シミュレーション) → 光の輸送 → 像、の順で生まれる絵。
  コースティクスは描く模様ではなく、水面の形から光が集まって"発生"するものにする。

## 新アーキテクチャ (web/shader.js と env.js の中核を置換)
### 1. 水面の状態 (ステートフルな波高フィールド)
- GPU 上に波高フィールドを保持する (RenderTarget / DataTexture)。
  単なる時刻関数ではなく、環境に駆動されて時間発展する「状態」にする。
- スペクトル合成: 24〜48 本の方向性波成分の和。
  - 振幅は風速から物理的に決める (Phillips スペクトル型:
    A(k) ∝ exp(-1/(kL)^2) / k^4、L = V^2 / g、V=風速)。
    風が強いほど大きな波が立ち、弱いほど細かいさざ波だけが残る。
  - 方向分布は風向を中心に広がる。
  - 位相は分散関係 ω = sqrt(g·k) で進める (大きな波はゆっくり、小さな波は速く)。
  - 風の入力が変わったら、状態は即座に切り替わらず数秒かけて追従する (慣性)。
- 波高から法線を求める (解析的微分または有限差分)。
  グリッター用の微細法線も、より小さい波成分として同じ状態に含める。

### 2. 光の輸送 (状態からのみ像を作る)
- **屈折**: 視線が水面で屈折して像が揺れる。IOR 1.333、波長で僅かに変える
  (色分散)。変位量は水深と法線から決まる。
- **コースティクス = 集光の計算**: 太陽光が水面で屈折し、水深 d の像面に
  落ちる位置の写像 q(p) を波高フィールドから求め、そのヤコビアン
  (面積の伸縮率) の逆数で光の密度を出す。集まった所は明るく、
  広がった所は暗くなる (**乗算による光の再分配**。白を加算で塗らない)。
  - 水深が深いほど焦点はぼける: ヤコビアン場を水深に応じた広さで
    多点サンプリングして滑らかにする。
  - 値はトーンマップでロールオフし、白飛びさせない。
- **水の体**: Beer-Lambert 型の吸収を水深・濁度・色素で計算し、
  散乱色を混ぜる。今のティント処理をこの形に寄せる。
- **水面の映り込み**: フレネルで空の色を薄く映す。太陽方向の微細法線で
  グリッター (点のきらめき) が出る。今のような筋状のグリッターは禁止。

### 3. 8秒ループの維持 (書き出し仕様)
- ループ書き出し時は各波成分の角速度を 8 秒で 2π の整数倍に量子化し、
  継ぎ目なしを保つ (視覚的な差は無視できる範囲で)。
