# BRIEF-V4-2-3 — H の不合格は生成側か、物差し（パッチ寸法）か（監査のみ）

Workdir: `D:\yohey2026\dsh\muse\caustics-filter\offline`

## 問い

v4-2.2 で構造関数 H だけが落ちた（0.151、帯 0.70–0.85）。レポート §5 の
切り分けでは、純粋な fBm（H_gen=0.79）の場でも同じ推定量・同じ 0.6 m
パッチでは 0.48–0.66 にしかならない。では **長い床で測ればどうなるか**。
生成側の性質か、物差しの限界かをこれで決める。レンダリングはしない。

## 作業

新規ファイルのみ: `run_v4_2_3.py`。既存ファイルは一切変更しない。
`bed_gen2` は import して無改造で使う。構成パラメータは v4-2.2 の
最終ビルドと同一（numbers-v4-2-2.json の構成記録から verbatim）。

1. **帯状床**: 流れ方向に長い床（目安 3.0 m × 0.6 m、解像度は
   v4-2.2 と同じ 0.2930 mm/px 級。メモリが不足する場合は流れ方向の
   断面列（トランセクト列）として構成してよいが、その場合は
   「2次元場ではなく断面列である」ことを明記する）。
2. **同じ推定量で測る**: 構造関数 H を v4-2.2 と同一の推定手順で、
   ラグ 4–20 cm の帯と、それより大ラグ（最大で帯状床の長さの 1/3 まで）
   の両方で測る。ラグ依存の曲線そのものを出す。
3. **対照**: 粒なしの基盤のみ（fBm H_gen=0.79 + 低次モード + 歪み変換、
   v4-2.2 と同一構成）を同じ形状・同じ推定量で測る。
4. v4-2.2 の 0.6 m パッチでの再測定も同じコードで併記し、
   「パッチ寸法だけが違う」比較にする。

## 判定の形（合否ではなく切り分け）

- 帯状床で粒床の H が帯（0.70–0.85）に届く → ゲートはパッチ寸法を
  測っていた。stage 2 の床は「長い床では H も成立」と記録する。
- 届かない → 生成側に複数スケールの組織が足りないことが確定。
  どのラグ帯で指数が落ちるかを曲線で示す。
- どちらの場合も、対照（基盤のみ）の H を並べて解釈の根拠にする。
