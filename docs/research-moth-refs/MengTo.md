## 対象投稿の中身
- 自宅を Opus 5.5 で three.js シーン化。ブラウザで歩行可能、ライティング変更・描画スタイル切替可能。チュートリアル動画撮影用の「実写の代わりのセット」。
- 「All objects are code using the scoring system」— 全オブジェクトがコード生成で、後述の採点ループで作られている。
- 前段として 2026-11-07 頃に自室を写真・動画参照で three.js 再現した事例あり（ai-primer 報道）。Blender は重くてマルチタスクを妨げるため three.js を選んだ、と明言。

## scoring system（本人の手法の核、ai-primer 報道より）
- シーンの要素をカードに分ける（船の例： 船体／水／地形／建物／その部品群）。
- 各要素を AI 自身が採点し、**8/10 に届くまで直す**。制限はトークン量と時間の予算で切る。
- 効用は本人の言葉で「品質の下限が明示される」こと。「もっと詳しく」という曖昧な修正指示の代わりになる。
- 人物・動物は「notoriously hard」で、キャラクタ系アセットは Meshy や Tripo3D が要る、というのが本人の結論（KOBATAKA と同型の結論）。

## 蛾への処方として効く点
- proto3 の合否を「パーツ別スコアカード＋下限（例：8/10）＋予算（試行回数）」で運用する型がそのまま使える。スコア項目は翅輪郭／腹部構造／翅面質感／接地に分解（SYNTHESIS (A)）。
- 写真・動画を参照に実物を再現する進め方（自室事例）は、蛾の写真参照モデリングと同構図。
