## D1：単一 seed・単一フレームの G-LINE 合否はモデルの性質ではない

**STANDS**（観測事実として）。

v4-1.10 の5本中0本が全窓通過、かつ正規化後も散らばりが残るという実測は、「単発 realization の合否をモデルの性質とみなすのは誤り」という主張を直接支持する。本番 seed が smooth y / bark x で FAIL したのも、ただの不利な引きに過ぎない可能性が高い。

**反論**：5本は「全通過が稀」を示すには十分だが、「決して起きない」を示すには不十分。もし realization の空間が多峰で、通過するモードが低頻度に存在するなら、単発合否は「そのモードに当たったかどうか」を表しており、モデルの性質の一部になりうる。また frame 24 固定のままなので、時間方向の変動も未評価。

## D2：窓ごとの比の分布で判定すれば合否はモデルの性質になる（R=5×F=3, n=15）

**WEAKENED**。

分布で見る方向性自体は正しいが、「n=15 と平均の標準誤差を明記すればモデルの性質になる」という条件付けは過大。

- フレームは独立ではない（D5 参照）ので実効 n はほぼ R=5 に近い。
- n≈5〜15 での q90 は極めてノイジー（特に右裾）。ブートストラップ区間が境界をまたぐ可能性が高いと自ら認めている時点で、判定の安定性は保証されない。
- 「モデルの性質」にするためには、少なくとも realization 間の分散構造（seed 依存か、より深いモードか）を分離する必要があるが、現状の設計にはその機構がない。

**反論**：平均の SE を明記しても、閾値自体が配置値であり、参照分布が写真1枚のジッターだけなら、「モデル vs 写真」の比較は依然として弱い参照に依存する。

## D3：写真側も分布として扱わねばならない。窓配置ジッターを測定床とするのは最小限の是正

**STANDS**（方向性として）。

1枚の写真の4窓を点として扱うのは、単発 seed と同じ誤りを反対側で繰り返す。ジッター sd を床として併記し、超過を σ 単位で見るのは合理的な最小限修正。

**反論**：ジッターは「同じ写真の窓位置ノイズ」であり、写真間の変動（撮影条件・水面状態・照明の違い）を捉えていない。写真側の真の不確実性はもっと大きい可能性が高い。測定床として使うなら「写真1枚＋ジッター」ではなく、複数写真の分布を取るべき。

## D4：判定規則「平均 ≤1.05 かつ q90 ≤1.25、全4窓」は実測の散らばりに較正されており、系統的超過と不利な引きを分ける

**WEAKENED**。

現状の数字（平均 0.95–1.12、最大 1.02–1.29）に対して「なんとなく収まる場所」に置いた配置値であることは自分で認めている。較正というより「観測ギャップへの後付け配置」に近い。bark y の系統的 +12%（+2.0σ）を落とす意図は見えるが、1.05 / 1.25 という具体的な数値の根拠は「実測の最大がそこにあるから」以上のものがない。特に q90≤1.25 は n が小さいときに過大に緩くなる（あるいは過大に厳しくなる）リスクが高い。

**反論**：もし realization をさらに増やしたときに平均が 1.08 前後に収束し、q90 が 1.30 を超えるなら、この閾値は「系統的超過を見逃す」方向に失敗する。逆に、たまたま低めの realization ばかり当たれば、不利な引きを系統的超過と誤認する。

## D5：1ループ内のフレームは独立標本ではない。実効標本数は realization 数で数えよ

**STANDS**。

2秒ループの frame 0/24/47 は強い時間相関を持つ（特に低周波のコースティクスパターン）。F=3 を n にそのまま加算するのは水増し。実効自由度はほぼ R に近い。

**反論**：完全に独立ではないが、ゼロ情報でもない。フレーム間の相関係数を実測して実効標本数を補正する方が正確。現状の「F を数えるな」は安全側だが、情報を捨てすぎている可能性はある。

## D6：G-LINE-stat と G-LINE2 は独立な2軸として併用できる

**WEAKENED**。

「量の分布」と「固定周期の突出」は概念的に直交しうるが、実測での相関が未検証。bark y で系統的に深い realization が、同時に prom2d も高くなりやすい構造があるなら、2軸は独立ではない。読み表の4組合せがすべて意味を持つ、という主張は現時点では仮説。

**反論**：G-LINE2 の写真中央値 21.1 vs 問題作 25.4（1.21×）は、すでに G-LINE の depth 超過と連動している可能性がある。相関行列を取らずに「独立」と宣言するのは早計。

## 設計の失敗条件（誤合格／誤不合格が出るケース）

1. **n=15（実効≈5）での q90 のノイズ**：ブートストラップ区間が 1.25 をまたぐ窓が頻発し、「未解決」が増えすぎてゲートとして機能しなくなる。あるいはたまたま狭い区間が出て誤って合格／不合格を出す。
2. **写真参照の薄さ**：写真1枚＋窓ジッターだけが床。別の日・別の水面状態の写真を取ると測定床が動き、同じモデルが合格⇔不合格を逆転する。
3. **フレーム間相関の過小評価**：F を完全に捨てると検出力が落ち、系統的超過を見逃す。逆に独立とみなすと過検出。
4. **閾値の配置値性**：土台が stage 2（本物の3D床など）に変わった瞬間に 1.05/1.25 は意味を失う。再較正を義務付けても、運用で忘れられたり、新しい参照写真が1枚しか用意されなかったりすると、再び単発判定に戻る。
5. **多重比較**：4窓すべてで条件を満たす、という AND 条件は、窓間の相関を無視している。独立なら実質的にかなり厳しいが、相関があるなら実質自由度が下がり、誤合格が増える。

## 見落としている機構・論点

- **窓定義の恣意性**：軸平行 5–15 px 帯という定義自体が、コースティクスの異方性やスケールに最適化されていない可能性。depth 以外の統計量（例えば帯域ごとのパワー比、スキューネス、空間周波数の重心）の方が分布の差を安定して捉えるかもしれない。
- **4窓の多重比較問題**：単純な AND は Bonferroni 的に厳しすぎるか、相関を無視して緩すぎるかのどちらか。窓間の共分散を考慮した同時検定か、あるいは主成分に落とす方が健全。
- **G-LINE2 との相関**：2軸が本当に独立かは未検証。もし depth の超過と prom2d の上昇が強く連動しているなら、「2軸併用」は見かけだけ。
- **realization の生成過程**：seed を変えるだけでは、モデルの latent 空間の重要なモードをサンプリングできていない可能性。特に時間方向（フレーム）と空間方向（seed）の分散構造が異なるなら、R×F の単純な格子は不適切。
- **正規化版でも散らばりが残るという事実の解釈**：振幅を揃えても残るなら、パターンの「形」の realization 依存性が強い。depth というスカラー1つで分布を判定するのは情報を捨てすぎている可能性がある。

## 採用するなら最低限直すべき点（優先順位つき）

1. **実効標本数の補正を必須化**（最優先）
フレーム間の相関係数を実測し、実効 n を R ベースで明示する。n=15 と書かない。q90 の不確実性をブートストラップではなく、より安定した推定量（例：平均＋k×sd、または分位点回帰）に置き換えるか、少なくとも「未解決」判定の運用ルールを厳密に書く。
2. **写真参照を複数枚に拡張**
窓ジッターだけでは不十分。最低でも異なる撮影条件の写真を数枚取り、写真側の分布（または測定床）をそれにする。1枚＋ジッターは「最小限」ですら足りない。
3. **閾値を「配置値」から「運用可能な再較正可能な値」に落とす**
1.05 / 1.25 を固定せず、「現状の参照分布に対する超過量」として相対化し、土台変更時は必ず再測・再配置する運用をゲートの定義に埋め込む。併せて、4窓の同時判定に多重比較補正か窓間相関を入れる。

以上。この設計は「単発判定の破綻を認識した」点では前進だが、統計的ゲートとして成立させるには標本サイズ・参照分布・閾値の根拠・軸間独立性のすべてがまだ薄い。
