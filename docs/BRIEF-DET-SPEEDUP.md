# BRIEF-DET-SPEEDUP — 本番 det_frame の高速化（等価性ゲート付き）

Workdir: `D:\yohey2026\dsh\muse\caustics-filter\offline`
前提測定: `out/prod-profile/REPORT-PROD-PROFILE.md`（cf-0048）。本番経路は `run_prod_v4.py`（loop8s）、1フレーム 49.222 s のうち段階 (b) `det.det_frame` が **43.321 s（88.0 %）**。内訳：σ0.75 px FFT ガウシアンは 0.257 s のみで、残り ≈99 % は方向ループ内の屈折＋スプラット（bincount）である。

## 目的

`det_frame` と同じ堆積を、同じ結果で速く計算する方法を作り、実測で示す。速くする実装そのものが目的で、見た目・物理の変更はしない。

## 対象の定義（実装の実態）

- `det.det_frame(fields, S, 2048, env, Q=25)`：太陽円盤 25 方向 × 2048² テクセルの Snell 屈折 → 双線形スプラット堆積（周期 2048² バッファ）→ 解析的除数 → σ0.75 px FFT ガウシアン。仕事量は 25 × 2048² = 104,857,600 レイ、現行 0.413 µs/レイ。
- 呼び出し側は `run_prod_v4.py` L156。条件は本番メイン条件（preset 1、S = 1.4755102041 m、深さ 0.6 m、seed 3255045276382562994）。

## 手順

1. **内訳の確定**：`det.py` の `det_frame` を読み、方向ループ内部（屈折計算／スプラット／除数／FFT）のどこに時間があるかを frame 0 で実測する。ベースライン（現行 det_frame の秒数）は高速版と**同じセッションで背中合わせ**に測る（マシンは共用で他ジョブが走っている可能性があるため、倍率を主結果とし、絶対値はその旨を注記する）。
2. **高速版の実装**：新規ファイル `det_fast.py`（offline 直下、新規のみ）に、同じ数学を速く計算する実装を置く。第一候補は Numba njit（float64、カーネル内の演算順序は現行と同等に保つよう努める）。ベクトル化の再構成でもよいが、計算内容（屈折式・スプラットの重み・周期境界・除数・ガウシアン）は変えない。
3. **等価性ゲート（必須・合否）**：測定ハーネス（`out/prod-profile/profile_prod_frame.py` の型。コピー側で差し替える。本番ファイルは編集しない）で frame 0 と frame 24 の2フレームを高速版で通し、本番成果物・現行版と比較する：
   - C 配列：本番 `out/prod/C-0000.npy` および現行 det_frame の出力と照合。**ビット一致が第一目標**。スプラットの加算順序が変わって一致しない場合は、max abs diff と相対差、C の統計（mean/std/p99/max）を必ず報告し、判定を分ける（ビット一致／数値等価（差が float64 の丸め誤差級）／不一致）。
   - 最終 PNG：本番 `out/prod/frame-0000.png` と画素一致するか。
   - ゲートを通らない実装は「速いが別物」として報告し、採用候補にしない。
4. **フレーム並列の見積もり**：1フレーム実行時のプロセス RSS を実測し、空き RAM × 0.7 で何ワーカー並列にできるかを示す。2ワーカー以上入る場合は、4フレームの実測（並列時の壁時計）を取り、直列見積もりと比較する。並列化は既存のフレーム本体をプロセスごとに呼ぶ形とし、計算内容は変えない。
5. **見積り**：高速化後の1フレーム秒数（直列）、48フレーム（2秒）／192フレーム（8秒）の所要時間を、並列なし／並列ありの両方で出す。
