## 背景（実測、v4-1.15 の結論）

- 面積保存メッシュ堆積（`transport_mesh.py`、718行）は正しさが実証済み（エネルギー保存 1e-12 級、G-PEAK PASS）。
- しかしサブ枠（窓 4.8×3.52 m、深さ 4.0 m、プリセット5の風）では格子収束が未決着：基準 512² で G-CONV FAIL（256² 比 std +46.7%）、上向き 1024² でも std −33.8% 動く。
- verbatim のままでは 1024² が 1フレーム 867 秒（48フレーム ≈ 11.6 時間）、2048² が 1フレーム 3125 秒（≈ 41.7 時間）で実行不能（v4-1.15 stage 0 の実測外挿）。
- 本人決定（2026-11-15）：「速い計算方法を先に作る」。速くなってから細格子で決着させる。

## 大原則の制約（絶対）

- 許されるのは**中立な数値**だけ：同じ面積保存メッシュ射影の計算を速くする。数学そのものを変える近似は禁止。
- 禁止の具体例：点スプラットや近似ラスタライズへの置換／ポリゴンクリッピングの省略・簡略化／被覆面積の近似／太陽円盤求積の変更／ゲート定義の変更。
- 浮動小数点の合算順序が変わることによる丸め差は許容するが、下の等価性ゲートで縛る。FP32 化はゲートを通る場合のみ可（通らなければ FP64 のまま）。
- フレーム間の並列化は可（フレームは独立で、1フレームの数学は不変）。1フレーム内部の数学を変える並列化は不可。
- 既存ファイル（特に `transport_mesh.py` と v4-1.15 の実行スクリプト）の振る舞いは変更しない。高速版は新規ファイル `transport_mesh_fast.py` に置き、verbatim は参照実装として残す。
