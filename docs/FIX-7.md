# FIX-7: 前方（フォワード）スプラッティングへの転換 — 面を「数える」方式に

対象: `caustics-filter/web/`（shader.js / app.js / env.js）
前提: 環境ノード→水の状態（波高場・法線場）の生成は FIX-5/6 のものをそのまま使う。変えるのは「光輸送の評価方法」だけ。パターン描画への回帰ではない（下記「方式の位置づけ」を dsh は RESULT.md に明記すること）。

## なぜ転換するか（メイン側の目視判定、FIX-5/FIX-6 両方不合格）
- FIX-5: プリセット1は均一な細粒、プリセット0は粒状ノイズ。面なし。
- FIX-6: 層バランス反転・相関長指標は改善したが、目視では (a) プリセット1は逆に弱くなり網目が消えた (b) プリセット0の粒は残存。パラメータ調整2ラウンドで未解決。
- 深掘り調査の第一診断がこれ: 本物の明るさは「着地点写像の全逆像に対する 1/|det J| の合計」。後方（ピクセルごと）ヤコビアンは原理的に1分岐しか数えられず、折り畳みの重なり＝明るい面が再現できない。Evan Wallace 方式・GPU Gems 系の実務標準は前方評価（面積比／フォトン蓄積）。

## 方式の位置づけ（ユーザー指定との整合）
- 環境→水の状態（波スペクトル・Choppy・法線場）は不変。コースティクスは引き続き水面状態から創発する。
- 変えるのは「同じ光輸送を、後方1分岐近似ではなく前方蓄積で正しく評価する」こと。これは描画トリックではなく評価精度の問題であり、FIX-2 で決めた物理路線の完成形。

## 実装指示
1. **コースティクスバッファの新設**: 内部解像度は描画解像度の 1/2（上限 512×512 程度、性能を見て調整可）の浮動小数または半浮動小数ターゲット（WebGL1: OES_texture_half_float / float 拡張を使い、不可なら 8bit＋加算ブレンド近似にフォールバック）。
2. **前方パス**: 水面をグリッド（例 256×256 頂点、波高場は現行の成分合成を頂点シェーダまたは JS 生成で共有）として、各頂点から太陽方向の屈折レイを飛ばし、仮想底面（水深ノードの深さ）への着地点を計算。隣接頂点との四角形（2三角形）の「水面側面積／底面側面積」比をその四角形の光量とし、着地点にガウス状フットプリント（半径＝太陽円盤ぶん＋1texel、FIX-6 の半径式を流用）で加算描画（ブレンド ONE, ONE）。
   - これにより折り畳み領域では複数四角形が重なって自動的に明るくなり、発散領域は薄くなる＝面と網目が同時に立つ。
   - 8秒ループ: 波高場が既にループ量子化されているため、そのまま周期一致する（数値確認すること）。
3. **合成パス**: 現行の HDR 合成を維持。Cn = バッファ値 / 平均（平均は JS 側で低頻度に推定するか、解析的正規化定数＋verify-node で較正）。L = photo × max(0.1, 1 + kc(Cn−1))、kc 既定 0.8。屈折による像の揺らぎ（サンプル座標の変位）は現行どおり別途適用。
4. **後方ヤコビアンの扱い**: 廃止するか、バッファが使えない環境でのフォールバックとして残す（コード分岐で明示）。グリッター（表面反射の点滅）は現行のものを維持。
5. **色分散**: 前方パスを RGB 3回に分けるのは重いので、着地点オフセットに IOR 差分（R 1.3313 / B 1.3393）を掛けた2枚（R用・B用）のバッファ＋G は中間、が上限。重ければ合成時にバッファの勾配方向へ ±δ シフトした近似でも可（RESULT.md に採用方式を明記）。
6. **性能**: スマホ 60fps が目標。グリッド解像度とバッファ解像度は uniform/定数で調整可能にし、デフォルトは中庸（グリッド 192×192、バッファ 384 程度）から始めてよい。verify-node の数値検証は CPU ミラーで従来どおり（密度統計: 平均1±0.15、min≤0.5、max 6〜12、隣接相関は FIX-6 水準以上）。
7. プリセット・UI・レシピJSONスキーマは不変。プリセット0/1 の kc・dgCap 等は新方式に合わせて再較正可（変更値を RESULT.md に記録）。

## 禁止事項（再掲）
- Hoskins型/Voronoi型など「水の状態と無関係な模様」の生成関数の追加。白の加算合成（最終合成段）。露出でのごまかし。
