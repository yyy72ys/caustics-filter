# 高忠実度オフラインパイプライン v1（WebGLの枠を外した物理経路）

## 目的と位置づけ
- 目的: リファレンス級のリアリティを持つコースティクスを、構造の数値で規定できる方法で生成する。判定は「視覚＋数値仕様」の両方。
- Webアプリはレシピ作成のフロントエンドとして残す。本パイプラインは同じレシピJSON（caustics-recipe/v1）を入力に、PC（RTX 3060 Ti）で重い物理計算を行う最終レンダリング経路。
- 今回のスコープ: **プリセット1（緑の川の浅瀬）の静止画1枚＋16フレームの短いテストクリップ＋数値レポート**。ループ本番（160フレーム）はメイン側のゲート通過後に別途発注する。

## パイプライン（環境 → 状態 → 光輸送 → 像）
作業ディレクトリ: `caustics-filter/offline/`（新規）。基盤: Python 3.10 + NumPy（必要なら CuPy を追加してよいが、まず NumPy で成立させる）。

### 1. 水の状態（連続スペクトル）
- Phillips スペクトルを波数空間でサンプリングし、FFT で高度場を生成する。グリッド **2048×2048**、パッチ一辺 S = 4×specL [m]（プリセット1: specL≈2.64 → S≈10.6m、Δx≈5mm）。
- 帯域: k はグリッドの最小波数から Nyquist まで（波長 数m〜約1cm、3桁）。方向分布は cos 型（風向中心）。微小波の減衰長 l≈0.005m。
- 変位: Choppy（水平変位 λ=0.85、既存知見と整合）。勾配場（法線用）も同時に得る。
- **ループ厳密化**: 各成分の角周波数 ω=sqrt(gk) を ω0=2π/8s の整数倍に量子化し、8秒で厳密に周期化する。位相はレシピのシードで決定的に固定。
- 高度・勾配は任意点で双三次補間して使えること（フォトン側・像形成側の両方が同じ状態を参照する）。

### 2. 光の輸送（フォトンマッピング）
- 毎フレーム **400万本** のフォトンをパッチ上に一様ジッターサンプリング。入射方向は太陽方向＋太陽円盤ジッター（角半径は基礎 0.00465 rad を空気の澄み具合で調整）。
- 水面で Snell 屈折（IOR は帯域別 R 1.33132 / G 1.33434 / B 1.33925、フォトンは RGB 3サブレイを持つ）。底面（z=−水深、レシピ値）との交点に、双線形スプラットで **2048×2048 HDR バッファ**へ蓄積。
- 密度推定として σ≈0.75px のガウシアン平滑。正規化はフォトン数とセル面積から物理的に行い、平均が保存されること（解析的な期待値との差を数値レポートに記録）。

### 3. 像の形成
- 写真の揺らぎ: 出力画素ごとに、同じ状態（高度・法線）で視線を屈折させ、底面のサンプル点をずらして写真を引く（Webアプリと同概念だが、状態の解像度と帯域が桁違い）。
- 底面光: 写真アルベド（線形化）×（コースティクス放射照度 × Beer-Lambert 減衰（水深・濁度・色素、帯域別）＋ 水中散乱のアンビエント項）。
- 水面反射: Fresnel（F0=0.02）で空のグラデーション（太陽高度・雲量から決まる空色）を同じ法線で反射し、HDR で加算。
- ACES フィルミックトーンマップ → sRGB。出力は写真ネイティブ寸法（735×539、動画用に 736×540 へスケール可）。

### 4. 数値レポート（numbers.json を必ず出す）
- 状態: グリッド、Δx、kmin/kmax [rad/m]、帯域の桁数
- 輸送: フォトン数、太陽円盤角半径、バッファ寸法
- 場の統計（トーンマップ前、線形）: 平均、CV、p50、p99、最大値。加えて ref1（refs/ref1-green-ripples.jpg）の水面領域クロップについて同じ統計を取り、並記する
- ループ: 状態が 8 秒周期であることの検証（t=0 と t=8 の状態配列の最大絶対差）
- 実行時間（状態生成・フォトン・像形成の内訳）
